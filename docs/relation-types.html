任務關聯類型 — 看得懂的版本

PMFlow 的「上下左右關聯」到底在講什麼。藍色的長條可以拖，橘色的會自己跟著動。

1四種依賴就是同一個句型換兩個字

介面上不會出現任何英文縮寫。你只要照著這個句型念，四種都成立。

等待任務
完成 / 開始
對方那一端
，
才能
開始 / 完成
我這一端

前半講「對方」的哪一端，後半講「我」的哪一端。兩個位置各有「完成 / 開始」兩種選擇， 二乘二就是全部四種——沒有第五種要背。

等待任務完成，才能開始　·　等待任務開始，才能開始
等待任務完成，才能完成　·　等待任務開始，才能完成

2四種排程依賴（會推動日期的）

拖藍色長條試試看。橘色長條會依照規則自動跟著跑——這就是甘特圖上拖一條、下游全部連動的原理。

3lag：中間要留幾天

每條依賴線都可以帶一個 lag（延遲天數），正數是「中間空幾天」，負數是「可以提前重疊」。

負的 lag 是排程壓縮最常用的手段。你不用把任務硬拆成兩半，只要讓下游提前重疊幾天，整個專案的關鍵路徑就縮短了。

4語意關聯（不會推動日期的）

另外四種關聯只是「記錄兩件事有關係」，純粹給人看、給搜尋用。拖來源，目標完全不動。

類型意思反向顯示為典型用法影響日期
相關相關（雙向對稱）相關 兩張單子講同一件事，但沒有先後 不動
阻擋阻擋被阻擋 「這個沒解決，那個就做不下去」——但你還不想動日期 不動
重複於重複於被重複 同一個問題被開了兩張單，留著當索引 不動
需要需要被需要 功能上需要另一個東西存在，但排程各走各的 不動
「阻擋」和「等待任務完成，才能開始」差在哪？兩個都是「A 沒好，B 不能動」，但後者會真的把 B 的日期往後推，「阻擋」只是掛個標記提醒你。
白話判斷法：你希望系統幫你自動改日期嗎？要 → 用「等待任務完成，才能開始」。不要，只想留個記號 → 用「阻擋」。

5「上下」和「左右」是兩件不同的事

這是最容易混的一組。它們在資料庫裡也是分開存的。

上下 ＝ 階層（父子）

一件大事拆成幾件小事。父任務的日期和完成率是子任務算出來的，你不用手動填。

機房搬遷（父） ├─ 盤點設備 ├─ 採購機櫃 └─ 實際搬運 父任務起日 = 子任務最早的起日 父任務迄日 = 子任務最晚的迄日 父任務完成率 = 子任務加權平均

左右 ＝ 依賴（前後）

兩件平輩的事誰先誰後。它們可以在不同父任務底下，甚至跨專案。

盤點設備 ──完成後開始──▶ 採購機櫃 採購機櫃 ──完成後開始──▶ 實際搬運 拖動「盤點設備」 → 採購機櫃 跟著往後 → 實際搬運 也跟著往後 （一路連鎖到底）
系統會擋掉的兩件事：不能在祖先和後代之間建立排程依賴（父子已經隱含關係了，再連會打架）；不能形成循環（A→B→C→A 會被擋下來並告訴你環在哪）。

6實際要用哪一個？

照你心裡想講的那句話去對，不要對英文縮寫。

你心裡想的是…就用拖來源時目標
「這個做完，那個才能開始」等待任務完成，才能開始
九成情況都是這個		往後推
「這兩件要一起開工」等待任務開始，才能開始跟著起跑
「這兩件要一起收尾」等待任務完成，才能完成跟著收尾
「那個要等這個開工後才能結束」等待任務開始，才能完成
很罕見		結束點跟著動
「這件事是那件事的一部分」父子階層（拖曳縮排）彙總
「有關係，但我不要它自動改日期」相關 / 阻擋不動
不確定就用「等待任務完成，才能開始」。市面上十套主流開源專案管理系統裡，沒有一套把四種都做完——大家的事實標準就只有這一種。另外三種是留給真的需要的人用的，不用勉強自己記。
